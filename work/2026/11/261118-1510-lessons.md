## Intent

The person asked to record three lessons, each at its level, as short preventive rules with no history, as the
core rules' section Lessons says; to add `lessons` to the kit's profile, and the kit's lessons file with its project
lesson; and to say in the record how lessons reach a session today: section 8 says a session receives them, but
nothing loads them yet (the hub will, from phase 2). The loading was to be built only if it is trivial and has one
reasonable design; otherwise it was to be noted in the record as an open point. Asked on 2026-11-18, from the home's
report `261118-1348`.

## Acceptance criteria

1. The kit's profile names its lessons file under `lessons`, and that file holds the kit's project lesson: stage
   paths explicitly when files outside the change are in the working tree.
2. The two lessons about the shell and inline scripts are placed at the technology or host level of the workflow's
   section 8 and reported, not written into the kit.
3. The record says how lessons reach a session today, and the loading is built or left as an open point with the
   reason.
4. The core rules, the template and the workflow do not grow; nothing personal enters the kit.
5. The kit's `verify` list passes.

## Strategy

A root file `LESSONS.md`, named by a new `lessons` key in `.hub/profile.yml`: one existing file, within the six of
`upkeep`. Of the three lessons, the one about `git add -A` concerns this repository's working tree and goes there; the
shell's expansion of double-quoted text is a property of the machine's shell, so a host lesson; inline scripts given
to `node -e` concern every project that uses Node.js, so a technology lesson. The last two go to the home. Loading is
judged against its designs before anything is built.

## Log

- 2026-11-18: record and branch created by a session that received the core rules and the template at start.
- `LESSONS.md` at the root, named by `lessons` in the profile, with the lesson about staging paths by name; a row
  for it in the README's table of the kit's files.
- The other two lessons are reported and written in the home, outside this pull request: the expansion of

- How lessons reach a session today: none is loaded. The SessionStart hook delivers the core rules and the template
  only; a session reads `LESSONS.md` only if it opens it. Section 8 describes the loading as it will be.
- Loading is not built: it is neither trivial nor of one design. The core rules and the template already use most of
  the 10,000 characters a hook can deliver (architecture, 3.1), so the project's lessons need a hook of their own
  that reads the profile, or an import from the project's own rules file, which is specific to the platform.
  Technology and host lessons are in the home, whose path the kit does not know: they need the hub or a setting of
  the installation. Open point for the person, to be decided with the hub of phase 2.
