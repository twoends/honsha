## Intent

The person asked for the kit's lowest Node.js version to be 26, and for everything else to be at its latest version too.
This answered the question why the kit's lowest Node.js version was 22 when a newer LTS exists. 22 had been set by the
session that built the checks on pull requests, as the oldest LTS still supported, and never discussed. On 2026-11-17
Node.js 26 is the active LTS (since 2026-10-28, end of life 2029-04-30); 24 and 22 are in maintenance (end of life
2028-04-30 and 2027-04-30). Asked on 2026-11-17, in the chat of a session on the kit.

## Scope and acceptance criteria

### In scope

- The kit's lowest Node.js version, wherever it is stated or tested.
- The versions of everything the kit pins: its development packages, the actions and the Claude Code version of its
  pipeline.

### Out of scope

- The home's Prettier version, which follows the kit's: changed in the home after this item, outside this pull
  request.
- Any change to the rules on dependencies, section 17 of the workflow, which is in another open pull request.

### Boundaries

- Every version taken follows section 17 as it is being merged: an ordinary update is taken only when released at
  least 14 days earlier.

### Acceptance criteria

1. The README, `package.json` and the pipeline say and test Node.js 26 as the lowest version; nothing in the kit still
   names 22 as a supported version.
2. `@types/node` follows Node.js 26.
3. Every pinned version is the latest one released at least 14 days before this item, or a stated exception.
4. The kit's `verify` list passes, locally and in the pipeline.
5. The home's radar entries name the versions taken; changed in the home after the merge.

- Prettier 3.10.1 and oxlint 1.94.0 were taken on 2026-11-17, before the 14-day rule existed: by that rule they are
  too new. The first project already pins Prettier 3.9.10 and oxlint 1.92.0.
- The pipeline's matrix runs Linux with Node.js 22 and Windows with Node.js 26; the PC runs Node.js 26.13.0.

### Design

- **Node.js 26:** `engines` `>=26`; the README; the pipeline's matrix becomes Linux and Windows, both on Node.js 26.
  `@types/node` 26.6.6.
- **Packages:** Prettier back to 3.9.10 and oxlint back to 1.91.0, the latest eligible versions; TypeScript stays at
  7.0.2. They move forward at the radar review of 2026-12-17, when the newer ones are eligible.
- **Actions:** already at their latest releases, pinned by commit; unchanged.
- **Claude Code in the pipeline:** an exception to the 14-day rule. It is not a dependency of the kit but the platform
  it runs on, and the pipeline's validator must be the version the kit is tried with on the PC, 2.1.325, which the
  README names. It follows the PC's version, not the registry.
- **Checks:** run the formatter, the linter and the type checker after the change; a difference that an older
  formatter or linter makes is fixed in the same work.

### Plan

1. Node.js 26 in `package.json`, the README and the pipeline; `@types/node` 26.6.6.
2. Prettier 3.9.10 and oxlint 1.91.0; install from the new lockfile without scripts; run the checks and fix what they
   report.
3. Verification, the checker, the pull request, the closing commit.
4. After the merge, in the home: Prettier 3.9.10, and the radar entries with the versions taken.

### Assumptions to confirm while building

- Prettier 3.9.10 formats the kit as 3.10.1 did, or with differences small enough to take in this item.
- oxlint 1.91.0 reports nothing new with the enabled groups.
- The scripts pass the type checker with the Node.js 26 definitions.

### Risks

- **A newer API used by mistake.** With the definitions of 26, the type checker accepts APIs that Node.js 24 lacks.
  Accepted: 26 is now the lowest version.
- **Users on Node.js 24.** They cannot run the plugin's hooks. Accepted by the person; the kit has no other user yet.
- **A conflict with the open pull request on dependencies,** which also touches the README. Resolved by merging the
  default branch into this branch after it lands.

### Decisions for the person

1. **Prettier and oxlint go back to the latest eligible versions,** 3.9.10 and 1.91.0, rather than staying on versions
   the 14-day rule would not take. Recommended: the rule then holds from today, and the newer versions come at the
   next review.
2. **Claude Code in the pipeline follows the PC's version,** 2.1.325, as an exception to the 14-day rule. Recommended.
