## Intent

The person asked to fix a defect of the guard found while working in the home: a command such as
`cd <other repository> && git push` was refused as a push to the default branch, because the guard judged the push in
the session's own folder, whose checkout was on `main`, and not in the folder the `cd` had moved to, which was on a
work branch. Asked on 2026-11-20, in the chat of a session on the kit, answering whether to fix it.

## Acceptance criteria

1. A `git push` that follows a `cd`, `pushd`, `Set-Location` or `Push-Location` in the same command line is judged in
   the folder that command moves to, when that folder exists; otherwise in the folder the guard had before.
2. A `cd` inside a subshell, in parentheses or in `$(…)`, does not move the commands after the subshell.
3. In a command of the PowerShell tool a backslash is read as part of a path, as PowerShell reads it, not as an
   escape.
4. Tests cover a push allowed and a push refused after a `cd`, the subshell, a folder that does not exist, and
   PowerShell's `Set-Location` with and without `-Path` on a path with backslashes.
5. The guard's opening comment and the workflow's section 14.3 say that it follows such a command.
6. The profile's `verify` passes.

## Strategy

`judge` walks the simple commands with a current folder, which starts as the session's and changes at each command
that changes the folder: its target resolved as `git -C` already resolves one (`gitDirectory`, which reads a Git
Bash path as a drive on Windows), `~` read as the user's folder, and no target or `-` left as they are, since the
guard cannot know the folder before. A target that does not exist leaves the folder unchanged, as the shell does when
`cd` fails. `simpleCommands` can mark where a subshell opens and closes, an option that its other callers do not
ask for, and `judge` restores the folder at the close. The hook passes which tool runs the command, and for the
PowerShell tool `simpleCommands` keeps a backslash as a character: otherwise `cd C:\…` would name a folder that does
not exist, and the fix would not reach the shell where such paths are written. The item is small: it changes which folder a push is judged
in, and in any case it cannot read it keeps today's behaviour; it touches no permission and no secret.
