## Scope and acceptance criteria

### In scope

- How a record enters the home's backlog and leaves it: an idea, a request kept for later, a `ready` item, a
  `dropped` one.
- The exception to "the default branch changes only through pull requests", in the core rules, where that rule is
  stated, and in the workflow's sections that depend on it (1, 3.3, 5, 13.4, 14.3).
- A script of `hub/` with its tests that captures and takes a backlog record; the check of commits where it must
  recognise the script's commits on the default branch.

### Out of scope

- The inbox with its verdicts and the lessons of a technology or of a host, which keep reaching the home in its work
  items; phase 3, which builds the inbox, decides whether they follow the backlog.
- The home's own instructions: once this item is merged, a home item points its "Dispatch" step to the script.
- The registry's moves, and every other change to the home, which keep their pull requests.

### Boundaries

- Only the script pushes to the default branch, and only commits that add or remove files under `backlog/`. The guard
  still refuses a push to the default branch typed by a session.
- A capture is on the hosting service when the script returns.
- The person does nothing for a capture to land.
- The kit's rules name no hosting service.

### Acceptance criteria

1. The core rules state the exception once: the backlog's records reach the home's default branch without a pull
   request, through the kit's script, in commits that only add or remove files under `backlog/`.
2. `node <kit>/hub/backlog.mjs add <project> <file>` commits the record to `backlog/<project>/` on the home's default
   branch and pushes it; `take <project> <id>` removes it, pushes, and prints the record. Neither touches the home's
   working tree.
3. The script refuses a project that is not in the registry, a file that is not a record, and anything outside
   `backlog/`; when the default branch has moved, it commits again on the new tip and pushes.
4. The check of commits accepts on the default branch a commit of the script, with its trailer, that only adds or
   removes files under `backlog/`, and refuses one that touches anything else.
5. The script's tests cover a first capture, a second one, a take, a refused project, and a push after the default
   branch has moved.
6. The profile's `verify` passes.

## Strategy

The pull request exists so that the person reviews a change before it lands. A captured idea changes nothing and has
nothing to review, so it is the one write that does not need one. The exception is made narrow by code, not by trust:

- **Capture.** `hub/backlog.mjs add` reads the registry from the home's default branch, refuses an unknown project,
  writes the record as `backlog/<project>/<id>-<slug>.md` in a temporary worktree of the default branch (the worktree
  code of `hub/projects.mjs` is shared), commits it with the trailer `Backlog: <id>`, and pushes it. If the push is
  refused because the default branch moved, it starts again from the new tip. About a second; the hub then answers
  that the idea is in the backlog.
- **Take.** When the item starts, `take` removes the file in the same way, and prints the record for the project's
  session, as a dispatched request does.
- **The guard is unchanged.** It reads the commands a session types; the push happens inside the script, the one way
  to it. A session that types `git push origin main` is still refused.
- **The check.** `checks/commits.mjs` reads the commits of a work branch, so the script's commits do not reach it
  there. Where the default branch itself is checked, a commit with the `Backlog` trailer that only adds or removes one
  file under `backlog/` is accepted, and any other direct commit is refused. Once the home's pipeline exists (item
  `261119-1202`), it runs that check on the default branch after each push.
- **Documents.** The core rules' "Delivery" gains one sentence for the exception, and the workflow's sections that
  speak of the default branch point to it; section 3.3's table keeps the backlog in `backlog/`.

Assumptions: the hosting service accepts a push to the default branch from an account that can write, which a private
repository of a free account does (the kit's GitHub piece, "What GitHub enforces"); a repository with branch
protection would need the script's account allowed to push there, which the piece says.

Risks: a mistake in the script could push something else to the default branch; its tests and its refusal of any path
outside `backlog/` keep that from happening, and git keeps every commit, so a wrong one is reverted by another.

Cost: about one full item: a script with its tests, a change to the commits check, and the rules and documents.
